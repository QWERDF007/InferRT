# InferRT 项目总览

## 1. 项目定位

`InferRT` 是一个围绕高并发深度学习推理、CUDA/CPU 图像与数值算子、特征检索与工业几何匹配构建的 C++/CUDA/Python 高性能基础架构库。

具备以下核心能力：

1. **核心契约与安全张量**：基于 SSOT 设计的 `Shape`、`TensorDesc`、`BufferView`、`PreprocessSpec`、`IExecutionDescriptor` 与 `IExecutableModel`，提供全路径算术溢出防护与强异常安全。
2. **多运行时模型生命周期**：提供 TensorRT 及可选的 ONNX Runtime、OpenVINO 后端入口；配置与重载事务具备强异常安全，`IModel` 同时提供 core 层 I/O 描述和执行适配。
3. **高并发异步推理引擎**：声明式 DAG 计算图（`PipelinePlan`）、动态批处理、多 GPU 负载均衡、优先级调度与 Promise Exactly-Once 交付。
4. **CUDA 图像算子库**：Resize、Normalize、Letterbox、CenterCrop、颜色转换、NMS、RoIAlign 等；NMS workspace 使用实例级 RAII 复用，稳态分配数据由 benchmark 验证。
5. **纯 C++ 算法算子库**：DBSCAN/HDBSCAN 聚类、B-Spline / 贝塞尔拟合，支持无 GPU 环境（Core-Only）。
6. **高级特征工程**：基于 Faiss 的高维向量相似度检索、高精度工业形状模板匹配器（`ShapeTemplateMatcher`）。
7. **Python 绑定**：基于 pybind11 与 DLPack 协议，提供 NumPy CPU 推理与 GPU 零拷贝双路径。

## 3. 核心模块与架构职责

### 3.1 `src/core`
负责最底层公共契约与数据结构：
- `irt::Status` / `irt::Exception` — 统一错误状态码与具备跨模块值语义的强异常
- `irt::Shape` / `irt::TensorDesc` / `irt::BufferView` — 单一事实来源张量契约与乘法溢出保护；元素计数和边界行为以 [`Tensor.hpp`](../src/core/include/inferrt/core/Tensor.hpp) 为准，测试入口为 [`tests/core/TestTensor.cpp`](../tests/core/TestTensor.cpp)
- `irt::PreprocessSpec` / `irt::PreprocessGeometry` — 预处理规格与解析后的缩放、padding、crop 几何契约；统一入口为 `resolvePreprocessGeometry()`，Engine、内置算子、sample 和 benchmark 复用同一规则；CVCUDA LetterBox parity 测试入口为 [`tests/cvcuda/TestLetterBox.cpp`](../tests/cvcuda/TestLetterBox.cpp)，使用独立 OpenCV CPU 参考且不依赖 model 模块
- `irt::IExecutionDescriptor` / `irt::IExecutableModel` / `irt::IExecutionPlan` — 共享 I/O 描述、model 执行和 session plan 契约；Engine runtime plan 与 model 复用同一套 `TensorInfo`，TensorRT 转换只在 adapter 内部发生
- 线程局部错误状态与跨 DLL/ABI 保护调用（`ProtectCall`）
- `GetVersionString()` 等构建元数据接口

### 3.2 `src/util`
系统工具与错误处理：
- CUDA 错误检查与自动转换（`IRT_CHECK_THROW` / `IRT_CHECK_LOG`）
- CPU 与 GPU 拓扑查询（`getCPUDeviceName`、`getGpuDeviceCount`）
- 跨平台路径与文件元数据解析

### 3.3 `src/ops`
独立纯 C++ 算法算子（支持在无 CUDA/OpenCV 的 Core-Only 环境编译与运行）：
- `irt::ops::DBSCAN` / `irt::ops::HDBSCAN` — 密度聚类算法
- `irt::ops::BSplineInterp` / `irt::ops::BezierFit` — 曲线与几何平滑
- 聚类私有实现按职责分为校验 [`ClusteringCommon.cpp`](../src/ops/priv/ClusteringCommon.cpp)、距离核 [`ClusteringDistance.cpp`](../src/ops/priv/ClusteringDistance.cpp)、邻域查询 [`ClusteringNeighborhood.cpp`](../src/ops/priv/ClusteringNeighborhood.cpp) 和树索引 [`ClusteringTrees.cpp`](../src/ops/priv/ClusteringTrees.cpp)。

### 3.4 `src/cvcuda`
CUDA 图像算子加速库：
- 算子集：`resize`、`normalize`、`letterbox`、`cvtColor`、`integral`、`NMS`、`RoIAlign`、`adaptiveThreshold`
- 内存策略：NMS 基于单一连续 256 字节对齐的 RAII device buffer，并在实例内复用 workspace。

### 3.5 `src/model`
多运行时模型生命周期管理：
- `irt::model::IModel` / `IModelConfig` — 模型接口与参数契约
- `irt::model::IBackendRuntime` / `CreateBackendRuntime(...)` — model 与 Engine 共用的 backend-neutral runtime loader 和 session execution contract
- `irt::model::CreateModel(...)` / `RegisterModel(...)` — 线程安全模型工厂与注册表
- 多后端支持：TensorRT、ONNX Runtime、OpenVINO
- 强异常安全：更新配置或重载失败时，无损保留旧运行时与配置

### 3.6 `src/engine`
高并发异步推理引擎：
- 声明式 DAG 计算图（`PipelineBuilder` / `PipelinePlan`）
- `InferenceEngine::Impl` 生命周期编排与 `StartResources` RAII 启动事务；CPU 阶段线程和批次完成由 `EngineStageWorkers` 私有模块独立持有
- `EngineScheduler`、`StageQueue`、`TicketPool`、`SlotExecutor`、`CompletionOrder`、`EngineMetricsFault` 私有组件
- 动态批处理、多设备负载均衡、优先级与丢弃策略
- Promise Exactly-Once 兑现契约
- `TensorRTRuntimePlan` 只负责 Engine 配置到 `IBackendRuntime` 的适配、能力校验和 session 转发；TensorRT engine 读取、binding 与 enqueue 的实现统一位于 model backend

### 3.7 `src/features`
特征检索与匹配：
- 基于 Faiss 的高维特征检索与图像相似度搜索
- 基于形状特征的高性能工业模板匹配器（`IShapeTemplateMatcher` / `createShapeTemplateMatcher()`）；ISA 选择隐藏在 features 内部
- 图像级索引实现位于 [`ImageSearchFaissIndex.hpp`](../src/features/priv/ImageSearchFaissIndex.hpp) / [`ImageSearchFaissIndex.cpp`](../src/features/priv/ImageSearchFaissIndex.cpp)，ROI 特征抽取契约位于 [`RoiFeatureExtractor.hpp`](../src/features/priv/RoiFeatureExtractor.hpp)，实现位于 [`RoiFeatureExtractor.cpp`](../src/features/priv/RoiFeatureExtractor.cpp)。

### 3.8 `src/python`
Python 绑定（`inferrt_model_py` 模块）：
- NumPy 路径（`infer()`）与 DLPack GPU 零拷贝路径（`infer_v2()`）
- 中间层特征提取（`forward_features()`）

## 4. 构建、测试与集成

- **Core-Only 构建**：`-DINFERRT_ENABLE_CUDA=OFF`，仅构建 core、util、ops 及测试，0 依赖 CUDA 与 OpenCV。
- **Full 构建**：`-DINFERRT_ENABLE_CUDA=ON`，启用 TensorRT、CUDA 算子、Engine 与 Feature 模块。
- **依赖配置入口**：Faiss、OpenCV、Python 和 TensorRT 的发现由 [`cmake/ConfigFaiss.cmake`](../cmake/ConfigFaiss.cmake)、[`cmake/ConfigOpenCV.cmake`](../cmake/ConfigOpenCV.cmake)、[`cmake/ConfigPython.cmake`](../cmake/ConfigPython.cmake) 和 [`cmake/ConfigTensorRT.cmake`](../cmake/ConfigTensorRT.cmake) 提供，共用来源解析实现见 [`cmake/ConfigDependencyDefaults.cmake`](../cmake/ConfigDependencyDefaults.cmake)；默认根目录统一登记在 [`tools/dependencies.yaml`](../tools/dependencies.yaml)。
- **安装前缀入口**：默认安装前缀与用户覆盖语义由 [`cmake/ConfigInstallPrefix.cmake`](../cmake/ConfigInstallPrefix.cmake) 统一管理。
- **安装与下游集成**：支持 `cmake --install` 并按组件导出 `InferRT::core`、`InferRT::util`、`InferRT::ops`、`InferRT::cvcuda`、`InferRT::model`、`InferRT::engine`、`InferRT::features`；无组件入口默认只加载 core，高级模块通过 `COMPONENTS` 请求，features 自动闭合 Faiss 等传递依赖。组件消费者、安装 relocation 和任意目录重定向由 [`tests/packaging`](../tests/packaging) 覆盖。
- **第三方运行库部署**：由 [`tools/package_runtime_dlls.py`](../tools/package_runtime_dlls.py) 按 [`tools/dependencies.yaml`](../tools/dependencies.yaml) 由用户显式部署；CMake 只安装 InferRT 自身目标并为 CTest 指向构建输出目录，不收集或复制第三方 DLL。ONNX Runtime 和 OpenVINO 的后端验收以 [`tests/python/test_backend_runtime.py`](../tests/python/test_backend_runtime.py) 的可行性验证为准；是否把运行库纳入部署集合由构建选项决定，实际不启用时无需部署。
