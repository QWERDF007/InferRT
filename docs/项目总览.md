# InferRT 项目总结

## 1. 项目定位

`InferRT` 是一个基于 C++ / CUDA / TensorRT 的轻量级推理工具库，当前仓库重点覆盖两类能力：

1. 模型推理能力：以图像分类模型为主，当前已实现 `AlexNet` 与多种 `ResNet` 变体。
2. CUDA 图像算子能力：当前已实现 GPU `resize`，并提供 C 风格接口与 C++ 封装接口。

从仓库结构和现有 sample 来看，这个项目目前更像一个“推理基础设施实验场 + 示例工程”：

- 一方面封装了 TensorRT engine 的构建、加载、保存与执行流程；
- 另一方面也在补齐通用的 CUDA 图像处理能力；
- 同时配套了样例、测试和导出头文件，具备继续扩展成完整推理库的基础。

当前版本号为 `0.0.1`，并带有 `-beta` 后缀。

## 2. 当前目录结构

仓库主体可以概括为下面几部分：

```text
InferRT/
|- cmake/                # CMake 配置、依赖发现、版本生成、导出配置
|- src/
|  |- core/              # 状态码、异常、版本、线程局部错误信息
|  |- cvcuda/            # CUDA 图像算子，目前以 resize 为主
|  |- util/              # CUDA 错误检查、断言等工具
|  |- model/             # TensorRT 模型抽象、权重加载、AlexNet/ResNet 实现
|- samples/
|  |- version/           # 版本信息输出示例
|  |- cuda_resize/       # CUDA resize 示例
|  |- model/             # AlexNet / ResNet 推理示例
|- tests/                # core / cvcuda / model 测试
|- assets/               # 测试图片、ImageNet 标签等资源
|- 3rdparty/             # googletest、vtest 等第三方依赖
|- InferRT-0.0.1/        # 当前导出的头文件产物目录
|- docs/                 # 文档目录
```

## 3. 模块分层与职责

### 3.1 core

`src/core` 是整个项目的底层公共模块，主要提供：

- `IRTStatus` / `irt::Status` 状态码体系；
- `irt::Exception` 异常封装；
- 线程局部错误信息存取；
- 版本号、分支、提交哈希、构建时间等版本信息接口。

这个模块是其他模块共同依赖的基础层。

### 3.2 util

`src/util` 提供一些偏工程化的辅助能力，例如：

- CUDA 调用错误检查；
- 断言相关工具；
- Debug 构建下暴露代码位置信息的编译定义。

它主要服务于项目内部实现和调试。

### 3.3 cvcuda

`src/cvcuda` 目前聚焦在 CUDA 图像处理算子封装，已经落地的能力是 `resize`：

- 提供模板化的 C 风格接口；
- 提供 `irt::cvcuda::Resize<T>` C++ 类封装；
- 支持 `uint8_t` 与 `float` 数据类型；
- 支持 `cv::INTER_LINEAR` 与 `cv::INTER_NEAREST`。

从测试和 sample 来看，这一模块的目标不是简单调用 OpenCV CUDA，而是实现一套可以被推理前后处理复用的自有 CUDA 算子层。

### 3.4 model

`src/model` 是当前最核心的业务模块，负责 TensorRT 模型侧流程，主要包括：

- `IModel` 抽象接口；
- `.wts` 权重文件加载；
- TensorRT network 构建；
- serialized engine 构建与反序列化加载；
- 执行上下文创建与推理执行；
- 模型工厂 `CreateModel`。

目前 `CreateModel` 已支持：

- `alexnet`
- `resnet18`
- `resnet34`
- `resnet50`
- `resnet101`
- `resnet152`

从接口设计上看，项目已经把“模型定义”和“engine 生命周期管理”分开了，后续继续加模型时，主要扩展点会落在 `buildNetwork(...)` 和对应的 `infer(...)` 实现上。

## 4. 当前已经实现的功能

### 4.1 TensorRT 模型推理

当前模型推理链路已经比较完整：

1. 读取 `.wts` 权重；
2. 构建 TensorRT network；
3. 生成 serialized network / engine；
4. 保存为 `.engine`；
5. 下次运行时优先复用已有 `.engine`；
6. 创建 execution context；
7. 执行推理。

这意味着 sample 已经不仅仅是“演示如何拼网络”，而是包含了比较实用的 engine 缓存机制。

### 4.2 AlexNet 分类示例

`samples/model/alexnet` 提供了完整的端到端流程：

- 用 `gen_wts.py` 从 `torchvision` 导出 `.wts`；
- 编译 `inferrt_sample_alexnet`；
- 对输入图像做 ImageNet 风格预处理；
- 输出 Top-3 分类结果。

### 4.3 ResNet 分类示例

`samples/model/resnet` 在 AlexNet 基础上扩展为多模型变体，当前支持：

- `resnet18`
- `resnet34`
- `resnet50`
- `resnet101`
- `resnet152`

从 sample 代码可以看到，这部分已经形成了统一的调用方式：按模型名创建实例，再执行 `buildOrLoad` 与 `infer`。

### 4.4 CUDA Resize 示例

`samples/cuda_resize` 用随机图像对 GPU `resize` 和 OpenCV `resize` 做结果对比，输出：

- 最大误差；
- 平均误差；
- 非零差异像素统计；
- 大于阈值的差异像素统计。

这个 sample 更偏算子验证与数值对齐。

### 4.5 版本信息示例

`samples/version` 可以输出：

- 版本号；
- 分支名；
- commit hash；
- 完整版本字符串；
- 构建时间。

说明项目已经把版本元信息纳入构建流程。

## 5. 构建与依赖情况

项目使用 CMake 组织构建，顶层会：

- 启用 `CUDA` 语言；
- 配置编译器与构建树；
- 检测 OpenCV；
- 检测 TensorRT；
- 引入第三方依赖；
- 根据选项构建 tests 与 samples。

当前关键依赖包括：

- CUDA
- TensorRT
- OpenCV
- GoogleTest
- vtest

样例权重导出脚本对应的 Python 侧依赖包括：

- `torch`
- `torchvision`
- `opencv-python`
- `timm`（ResNet sample 会用到）

## 6. 测试现状

项目已经有一套比较像样的测试骨架，覆盖三个方向：

### 6.1 core 测试

覆盖状态码、日志/错误等基础能力。

### 6.2 model 测试

重点是接口与异常路径验证，例如：

- `CreateModel` 工厂行为；
- 默认日志级别；
- `save/load/build/buildOrLoad` 的异常场景；
- 未初始化上下文时的 `infer` 行为。

这部分说明项目对“失败路径”和“接口契约”已经有意识地在收紧。

### 6.3 cvcuda 测试

`resize` 测试覆盖比较细，包括：

- `uint8_t` / `float`；
- C 接口与 C++ 类接口；
- 多尺寸、多通道、多缩放比例；
- `INTER_LINEAR` / `INTER_NEAREST`；
- 空指针、零尺寸、零通道等异常输入；
- 极端上采样、下采样和非对称缩放。

在当前仓库里，`cvcuda` 是测试最扎实的模块之一。

## 7. 当前项目特点

结合代码现状，这个项目有几个比较明显的特点：

### 7.1 以“可运行 sample”驱动实现

仓库里每个核心能力基本都有对应 sample，这让项目非常适合做：

- TensorRT 学习与验证；
- 新模型接入试验；
- CUDA 前后处理算子开发；
- engine 构建流程调试。

### 7.2 API 正在从 C 风格向 C++ 封装演进

例如 `cvcuda::resize` 同时保留了函数接口和 `Resize<T>` 类接口；模型侧也有 `IModel` 抽象。说明项目在兼顾“底层可控”与“上层易用”。

### 7.3 已具备扩展库形态的雏形

从 `add_plugin_library(...)`、导出头文件、版本生成和配置脚本来看，这个仓库不是一次性 demo，而是在往可复用库的方向走。

## 8. 当前阶段的边界

基于当前代码，可以看出项目还处在比较早期的建设阶段，主要边界包括：

- 模型类型仍以图像分类为主；
- 已实现模型数量不多，但结构已经搭好；
- `cvcuda` 算子还比较少，当前主要是 `resize`；
- `docs` 目录此前基本为空，说明文档体系还在补齐阶段；
- 顶层暂未看到统一的项目 README，理解仓库主要依赖源码目录和 sample 文档。

这并不是缺点，反而说明现在非常适合一边实现能力、一边把规范和文档补起来。

## 9. 总结

一句话概括，`InferRT` 当前是一个面向 TensorRT 推理与 CUDA 图像处理的 C++ 工程化基础库雏形，已经具备：

- 清晰的模块分层；
- 可运行的分类推理 sample；
- 可复用的 engine 构建/缓存流程；
- 一个测试覆盖较完整的 CUDA resize 算子；
- 持续扩展模型与算子的结构基础。

如果后续继续推进，这个项目很自然的演进方向会是：

- 扩展更多模型；
- 补齐更多前后处理 CUDA 算子；
- 完善顶层文档和接入说明；
- 进一步加强集成测试与发布产物管理。
