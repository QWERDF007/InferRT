# InferRT 项目总览

## 1. 项目定位

`InferRT` 是一个围绕 TensorRT 推理、CUDA 图像算子和特征检索能力构建的 C++/CUDA 工程化项目。

从当前仓库来看，它已经不是单一模型 Demo，而是具备以下几类能力的基础库雏形：

1. TensorRT 模型构建、序列化、加载与推理执行
2. 面向 CUDA 的图像算子封装
3. 面向分类模型的中间特征导出与特征专用推理
4. 基于特征向量的 Faiss 图像检索样例
5. 配套的样例、测试、基准和安装导出结构

当前顶层 CMake 版本为 `0.0.1-beta`。

## 3. 核心模块

### 3.1 `src/core`

负责最底层公共能力，主要包括：

- `IRTStatus` / `irt::Status` 状态码体系
- `irt::Exception` 异常封装
- 线程局部错误状态与保护调用
- 构建版本、分支、提交号、构建时间等版本信息接口

这是 `model`、`cvcuda` 和 `util` 的公共基础层。

### 3.2 `src/util`

当前已不只是简单断言工具，主要包括：

- CUDA 错误检查与错误码映射
- 错误消息格式化
- 路径辅助能力，例如项目根目录定位

从 `tests/util/TestUtil.cpp` 可以看出，这一层已经有独立的单元测试覆盖。

### 3.3 `src/cvcuda`

当前聚焦 CUDA 图像算子封装，已实现的算子仍以 `resize` 为主。

接口形式包括：

- 函数式接口：`irt::cvcuda::resize<T>(...)`
- 类接口：`irt::cvcuda::Resize<T>`

内部通过 `IOperatorImpl`、`OpResizeImpl.*` 等私有实现承载，已经具备继续扩展更多前后处理算子的结构基础。

### 3.4 `src/model`

这是目前最核心的业务模块，负责 TensorRT 模型生命周期管理和特征提取能力。

对外主入口包括：

- `irt::model::IModel`
- `irt::model::IModelConfig`
- `irt::model::CreateModel(...)`
- `irt::model::RegisterModel(...)`
- `irt::model::loadWeights(...)`

除传统分类推理外，`IModelConfig` 现在已经支持：

- `setFeatureTensorNames(...)`
- `setFeatureOutputTensorNames(...)`
- `setFeatureOnly(...)`

对应地，`IModel` 已支持 `forwardFeatures(...)`，用于执行中间特征张量导出。

### 3.5 内置模型

当前内置模型仍以分类网络和 ONNX 通道为主，共 16 个：

- `onnx`
- `alexnet`
- `mobilenet_v2`
- `mobilenet_v3_large`
- `mobilenet_v3_small`
- `vgg11`
- `vgg13`
- `vgg16`
- `vgg19`
- `resnet18`
- `resnet34`
- `resnet50`
- `resnet101`
- `resnet152`
- `wide_resnet50_2`
- `wide_resnet101_2`

其中：

- 内置分类模型通过 `.wts` 构建 TensorRT network
- `onnx` 模型通过 ONNX Parser 构建 engine
- 内置分类模型支持按约定的特征 key 导出中间层
- `onnx` 路径当前不支持通过该 API 选择内部特征层

## 4. 当前已具备的能力

### 4.1 TensorRT engine 生命周期封装

模型模块已经形成完整的工程化闭环：

1. 读取 `.wts` 或 `.onnx`
2. 构建 TensorRT network / engine
3. 保存 `.engine`
4. 后续优先复用已有 engine
5. 创建 execution context
6. 查询和绑定输入输出张量
7. 执行推理或特征前向

### 4.2 分类推理样例

`samples/model/classification` 是当前统一的分类模型样例入口，负责：

- `.wts` 权重导出
- 标准 ImageNet 预处理
- 调用 `CreateModel(...)`
- 输出分类结果

### 4.3 ONNX 推理样例

`samples/model/onnx` 展示了从 PyTorch 导出 ONNX 到 TensorRT 推理的整条链路，适合验证非内置网络结构的接入方式。

### 4.4 中间特征导出能力

这是相较旧版总览最大的变化之一。

当前项目已经支持：

- 在 `IModelConfig` 中声明要导出的特征层
- 生成特征裁剪网络
- 在默认分类推理引擎之外，额外维护特征引擎
- 通过 `featureOnly=true` 直接构建纯特征提取模型实例
- 通过 `forwardFeatures(...)` 导出多个中间层张量

这意味着 InferRT 已经从“只做最终分类输出”扩展到“支持中间表征分析与下游特征应用”。

### 4.5 特征对比样例

`samples/model/feature_extract` 提供：

- C++ 侧特征张量导出
- 与 PyTorch/timm 参考结果的数值比对脚本
- 针对中间层张量的误差统计

这使得特征能力不仅可用，而且具备可验证路径。

### 4.6 基于 Faiss 的图像检索样例

`samples/model/image_search` 基于内置分类模型的中间特征构建 Faiss 索引，支持：

- 扫描图库目录
- 提取图库和查询图的特征向量
- 建立或复用 `.faiss` 索引
- 返回 top-k 相似图像

这说明项目已经开始向“推理结果服务下游任务”延伸，而不局限于分类分数输出。

### 4.7 CUDA Resize 算子链路

`resize` 仍然是当前最完整的算子能力链路，具备：

- 样例：`samples/cuda/resize`
- 测试：`tests/cvcuda/TestResize.cpp`
- 基准：`benchmark/cvcuda/resize`

### 4.8 版本信息接口

`samples/version` 可以输出版本、分支、提交号和构建时间，说明版本元信息已纳入构建系统。

## 5. 构建与依赖

项目使用 CMake 组织构建，顶层主要开关包括：

- `INFERRT_BUILD_TESTS`
- `INFERRT_BUILD_DOCS`
- `INFERRT_BUILD_SAMPLES`
- `INFERRT_ENABLE_SANITIZER`
- `INFERRT_BUILD_BENCHMARK`

关键依赖包括：

- CUDA
- TensorRT
- OpenCV
- GoogleTest
- Google Benchmark
- cxxopts
- vtest

可选依赖包括：

- Faiss：当前由 `cmake/ConfigFaiss.cmake` 配置，`image_search` 样例依赖它

Python 脚本和样例侧依赖包括：

- `torch`
- `torchvision`
- `opencv-python`
- `timm`

## 7. 当前项目特征

结合当前代码，项目有几个比较明显的阶段性特征：

### 7.1 已经形成“库 + 样例 + 测试 + 基准 + 导出”的工程形态

整体结构已经具备持续演进基础库项目的基本面，而不是一次性演示代码。

### 7.2 模型层正在从分类推理扩展到通用特征服务

特征裁剪网络、`forwardFeatures(...)`、特征对比样例和图像检索样例，说明模型层抽象正在向下游检索/分析类任务延伸。

### 7.3 ONNX 通道仍然是通用化入口

内置模型之外，ONNX 路径仍是 InferRT 对外扩展网络结构的主要入口。

### 7.4 `cvcuda` 仍处于早期，但接口形态已经稳定

算子数量还少，但结构已经不是一次性 kernel demo，后续适合继续补齐 normalize、pad、color convert、warp、layout transform 等算子。

### 7.5 构建系统开始引入可选能力分层

Faiss 作为可选依赖接入，说明项目正在从“单一核心库”往“核心库 + 可选扩展样例”演进。

## 8. 当前边界与不足

按当前代码状态，项目仍存在这些边界：

- `cvcuda` 目前实装算子仍然主要是 `resize`
- benchmark 仍集中在单算子层面
- ONNX 模型暂不支持基于 `featureTensorNames` 的内部特征导出
- Faiss 配置当前偏本地固定路径，跨机器可移植性一般
- 样例目录命名存在一次重命名残留，文档和构建脚本需要进一步统一

## 9. 建议优先补充的文档

基于当前项目现状，后续最值得补齐的文档包括：

1. 模型接入指南：如何新增一个内置模型
2. 特征提取指南：如何声明特征层、如何理解 `featureOnly`
3. ONNX 使用指南：输入输出命名约定、动态 shape 约束
4. `cvcuda` 算子开发指南：如何新增一个算子
5. Faiss 图像检索样例说明：索引格式、复用策略、依赖准备
6. 构建环境指南：CUDA / TensorRT / OpenCV / Faiss 的准备方式

## 10. 一句话总结

一句话概括：`InferRT` 当前已经从一个 TensorRT 分类推理工程，演进为一个同时覆盖推理、特征提取、图像检索样例和 CUDA 图像算子封装的 C++ 基础库雏形。
