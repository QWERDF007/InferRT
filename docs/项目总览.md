# InferRT 项目总览

## 1. 项目定位

`InferRT` 是一个围绕 TensorRT 推理与 CUDA 图像算子的 C++/CUDA 工程化项目。当前仓库已经不只是一个单点 Demo，而是具备了基础库、样例、测试、基准和导出产物的完整雏形。

从现有代码来看，项目主要覆盖两条能力线：

1. 模型推理能力  
   基于 TensorRT 封装模型构建、序列化、加载、运行时张量查询与推理执行。
2. CUDA 图像算子能力  
   提供可复用的图像处理算子接口，当前已经实现 `resize`，同时保留了函数式接口和 C++ 面向对象封装。

当前 CMake 顶层版本为 `0.0.1`，并带有 `-beta` 后缀。

## 3. 核心模块

### 3.1 `src/core`

负责底层公共能力，主要包括：

- `IRTStatus` / `irt::Status` 状态码体系
- `irt::Exception` 异常封装
- `ProtectCall` 与线程局部错误状态转换
- 版本号、分支、提交号、构建时间等版本信息接口

这是整个项目最基础的一层，被 `cvcuda` 和 `model` 共同依赖。

### 3.2 `src/util`

提供工程化辅助能力，当前主要包括：

- CUDA 错误检查
- 断言工具

这部分更偏内部基础设施，用于减少 CUDA/TensorRT 代码中的样板错误处理。

### 3.3 `src/cvcuda`

当前聚焦 CUDA 图像算子封装，已实现能力为 `resize`。

接口层面同时提供：

- 函数式接口：`irt::cvcuda::resize<T>(...)`
- 类封装接口：`irt::cvcuda::Resize<T>`

内部实现由 `priv/OpResizeImpl.*` 承载，说明该模块已经在朝“可扩展算子层”演进，而不只是单个 CUDA 核函数示例。

### 3.4 `src/model`

这是目前最核心的业务层，负责 TensorRT 模型生命周期管理。

对外主入口包括：

- `irt::model::IModel`
- `irt::model::IModelConfig`
- `irt::model::CreateModel(...)`
- `irt::model::RegisterModel(...)`
- `irt::model::loadWeights(...)`

内部以 `priv::IModelImpl` 为统一基类，集中管理：

- 模型配置
- TensorRT engine / context / logger / stream
- engine 构建、保存、加载
- 运行时 I/O 张量查询
- Tensor 地址绑定

当前内置模型共 16 个：

- `onnx`
- `alexnet`
- `mobilenet_v2`
- `mobilenet_v3_large`
- `mobilenet_v3_small`
- `vgg11`
- `vgg13`
- `vgg16`
- `vgg19`
- `resnet18`
- `resnet34`
- `resnet50`
- `resnet101`
- `resnet152`
- `wide_resnet50_2`
- `wide_resnet101_2`

其中：

- 分类模型通过 `.wts` 构建 TensorRT network
- `onnx` 模型走 ONNX Parser 路径，从 `.onnx` 构建 engine

## 4. 当前已经具备的能力

### 4.1 TensorRT engine 生命周期封装

模型模块已经形成较完整的调用闭环：

1. 读取权重或 ONNX
2. 构建 TensorRT network / engine
3. 保存 `.engine`
4. 下次优先复用已有 `.engine`
5. 创建 execution context
6. 绑定输入输出张量地址
7. 执行推理

这意味着项目已经具备实用化的 engine 缓存机制，而不是只做网络定义演示。

### 4.2 分类模型共享样例

`samples/model/classification` 现在是统一分类样例入口，不再局限于 AlexNet 或单个 ResNet。

它负责：

- 导出 `.wts`
- 执行标准 ImageNet 预处理
- 调用 `CreateModel(...)`
- 输出分类结果

### 4.3 ONNX 推理样例

`samples/model/onnx` 展示了另一条完整链路：

- PyTorch 导出 ONNX
- ONNX -> TensorRT engine
- 从 engine 读取输入输出张量元数据
- 完成推理与结果打印

这条路径对接“非内置网络结构”尤其重要。

### 4.4 CUDA Resize 算子

`samples/cuda/resize`、`tests/cvcuda/TestResize.cpp` 和 `benchmark/cvcuda/resize` 共同说明：

- 该算子既有功能样例
- 也有数值正确性测试
- 还有性能基准入口

这是当前仓库里最完整的一条“算子开发链路”。

### 4.5 版本信息接口

`samples/version` 可以输出版本、分支、提交号和构建时间，说明版本元信息已纳入构建流程。

## 5. 构建与依赖

项目使用 CMake 组织构建，并默认启用以下能力开关：

- `INFERRT_BUILD_TESTS`
- `INFERRT_BUILD_SAMPLES`
- `INFERRT_BUILD_BENCHMARK`

关键依赖包括：

- CUDA
- TensorRT
- OpenCV
- GoogleTest
- vtest

样例脚本侧还依赖：

- `torch`
- `torchvision`
- `opencv-python`
- `timm`（部分模型/导出路径会使用）

## 6. 测试与验证现状

当前测试主要分为三块：

### 6.1 `tests/core`

验证状态码等基础能力。

### 6.2 `tests/model`

重点覆盖模型工厂、生命周期、异常路径、日志和 ONNX 模型接口行为。  
这部分对 API 契约和失败路径的关注比较明确。

### 6.3 `tests/cvcuda`

重点覆盖 `resize` 在不同：

- 数据类型
- 插值方式
- 尺寸组合
- 异常输入

下的行为，是目前测试覆盖最扎实的模块之一。

## 7. 当前项目特征

结合代码现状，这个仓库有几个比较明显的特征：

### 7.1 已经形成“库 + 样例 + 测试 + 基准”的工程形态

不仅有 API 和实现，还有：

- `samples/` 用于演示
- `tests/` 用于回归验证
- `benchmark/` 用于性能评估

整体形态已经很像可持续演进的基础库项目。

### 7.2 模型层抽象已经比较清晰

通过 `IModel -> priv::IModelImpl -> 具体模型` 的分层，对外接口稳定，对内可扩展性也比较好。

### 7.3 ONNX 路径让项目不只服务于内置模型

这很重要。它意味着 InferRT 不只是“手写几个 torchvision 网络”的项目，而是在向通用 TensorRT 推理入口延伸。

### 7.4 cvcuda 模块还很早，但方向是对的

当前只有 `resize`，但接口已经抽象成算子层。如果后续继续补齐 normalize、pad、color convert、warp、layout transform 等前后处理算子，这一层会非常有价值。

## 8. 现阶段边界

当前项目仍然处于早期到中早期阶段，主要边界包括：

- 图像算子数量还少，`cvcuda` 目前主要是 `resize`
- benchmark 覆盖面还不大
- 顶层用户文档体系还在补齐中
- 模型样例目前主要围绕 ImageNet 风格分类与 ONNX 推理

不过从结构上看，仓库已经把后续扩展最关键的骨架搭好了。

## 9. 建议的后续文档方向

从现在的项目形态出发，后续最值得继续补的文档包括：

1. 模型接入指南：如何新增一个内置模型
2. ONNX 使用指南：推荐输入输出约定、动态 shape 约束
3. CUDA 算子开发指南：如何新增一个 `cvcuda` 算子
4. 构建指南：CUDA / TensorRT / OpenCV 环境准备
5. 测试矩阵：不同平台与关键依赖版本的覆盖策略

## 10. 一句话总结

一句话概括：`InferRT` 当前是一个面向 TensorRT 推理和 CUDA 图像处理的 C++ 基础库雏形，已经具备了清晰的模块边界、可运行的样例、可回归的测试，以及继续扩展为完整推理库的结构基础。
