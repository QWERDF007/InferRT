# InferRT 项目总览

## 1. 项目定位

`InferRT` 是一个围绕 TensorRT 推理、CUDA 图像算子和特征检索能力构建的 C++/CUDA 工程化项目，并通过 pybind11 导出完整的 Python 接口。

从当前仓库来看，它已经不是单一模型 Demo，而是具备以下几类能力的基础库：

1. TensorRT 模型构建、序列化、加载与推理执行
2. pybind11 Python 绑定，支持 NumPy 和 DLPack（GPU 零拷贝）双路径推理
3. 面向 CUDA 的图像算子封装
4. 面向分类模型的中间特征导出与特征专用推理
5. 基于特征向量的 Faiss 图像检索模块与样例
6. 通用 TensorRT 维度、数据类型和 CUDA buffer 工具
7. 配套的样例、测试、基准和安装导出结构

当前顶层 CMake 版本为 `0.0.1-beta`。

## 3. 核心模块

### 3.1 `src/core`

负责最底层公共能力，主要包括：

- `IRTStatus` / `irt::Status` 状态码体系
- `irt::Exception` 异常封装（Python 侧映射为 `InferRTError`）
- 线程局部错误状态与保护调用
- 构建版本、分支、提交号、构建时间等版本信息接口

### 3.2 `src/util`

- CUDA 错误检查与错误码映射
- 错误消息格式化
- 路径辅助能力，例如项目根目录定位

### 3.3 `src/cvcuda`

CUDA 图像算子封装，当前已实现 `resize`。接口形式包括：

- 函数式接口：`irt::cvcuda::resize<T>(...)`
- 类接口：`irt::cvcuda::Resize<T>`

内部通过 `IOperatorImpl`、`OpResizeImpl` 等私有实现承载，具备扩展更多前后处理算子的结构基础。

### 3.4 `src/model`

最核心的业务模块，负责 TensorRT 模型生命周期管理和特征提取能力。

对外主入口包括：

- `irt::model::IModel` — 模型接口
- `irt::model::IModelConfig` — 模型配置
- `irt::model::CreateModel(...)` — 模型工厂
- `irt::model::RegisterModel(...)` — 模型注册
- `irt::model::loadWeights(...)` — 权重加载
- `irt::model::DeviceBuffer` / `HostBuffer` — 设备端/主机端 RAII buffer
- `irt::model::elementCount(...)`、`elementSize(...)`、`dataTypeToString(...)`、`checkCuda(...)` — 模型层通用工具

`IModelConfig` 支持的配置项：

- `num_classes`、`inputShape` / `inputShapes`
- `inputTensorNames`、`outputTensorNames`
- `featureTensorNames` — 要导出的中间层 key
- `featureOnly` — 是否构建纯特征提取模型（不包含分类头）

`IModel` 关键方法：

- `build(weights_file)` / `load(engine_file)` / `save(engine_file)` / `buildOrLoad(weights_file)`
- `infer(buffers, stream, non_blocking)` — CUDA 缓冲区推理
- `forwardFeatures(buffers, stream, non_blocking)` — 特征提取前向

分类推理和特征提取共享统一的 `TRTParams` 运行时（engine、context、stream），避免了此前双运行时导致的状态不一致问题。

`model` 模块中的工具职责已经拆分：

- `Utils.hpp/.cpp`：权重/标签加载、TensorRT 维度和数据类型格式化、CUDA 状态检查、ImageNet 预处理工具
- `Buffers.hpp/.cpp`：参考 TensorRT sample 的 `GenericBuffer` 设计，提供 `DeviceBuffer` 和 `HostBuffer`

### 3.5 `src/features`

面向模型特征向量的上层功能模块。当前包含 `irt::features::ImageSearch`：

- 使用内置分类、ViT、DINO 模型的指定中间层提取特征
- 按 TensorRT engine 的真实输入尺寸执行预处理，兼容 DINOv2/DINOv3 默认输入尺寸
- 对特征做 L2 归一化后构建 Faiss 内积索引
- 支持索引构建、索引复用、图库路径映射保存和 Top-K 相似图片查询
- 提供 `isImageFile()`、`collectGalleryImages()`、`defaultIndexPath()` 等辅助接口

该模块依赖 Faiss；当 Faiss 不可用时，CMake 会跳过 `features` 模块、对应测试和 `image_search` 样例。

### 3.6 `src/python` — Python 绑定

通过 pybind11 将核心模型能力导出为 `inferrt_model_py` Python 模块。构建需要 `-DINFERRT_BUILD_PYTHON=ON`。

**模块结构：**

| 名称 | 类型 | 说明 |
|------|------|------|
| `irt.ModelConfig` | 类 | 模型配置，属性：`num_classes`、`input_shape`、`input_tensor_names`、`output_tensor_names`、`feature_tensor_names`、`feature_only` |
| `irt.Model` | 类 | 模型实例，提供 `infer()`、`infer_v2()`、`forward_features()` |
| `irt.create_model(name, config)` | 函数 | 模型工厂 |
| `irt.is_supported_model(name)` | 函数 | 模型注册表查询 |
| `irt.get_registered_model_names()` | 函数 | 列出所有已注册模型 |
| `InferRTError` | 异常 | 对应 C++ `irt::Exception` |

**两种推理路径：**

| | `infer()` | `infer_v2()` |
|---|---|---|
| 张量类型 | NumPy ndarray | NumPy ndarray 或 DLPack 实现者（如 `torch.Tensor`） |
| 输出分配 | 可选（自动分配） | 必需（调用者提供） |
| CUDA Stream | 内部管理 | 调用者通过 `stream_ptr` 控制 |
| 数据路径 | 始终 Host↔Device | GPU 张量时零拷贝 |
| 适用场景 | 标准 CPU 推理 | GPU 驻留数据 + 外部 stream 管理 |

`infer_v2()` 基于 DLPack 协议实现，当传入 PyTorch CUDA 张量时，直接复用其设备指针，避免 Host↔Device 拷贝。`forward_features()` 也支持 NumPy 路径，返回中间层特征。

## 4. 内置模型

当前内置模型注册 key 共 76 个（含兼容别名，覆盖分类网络、ViT/DINO 主干和 ONNX 通道）：

- `onnx`
- `alexnet`
- `googlenet`
- `mobilenet_v2`、`mobilenet_v3_large`、`mobilenet_v3_small`
- `vgg11`、`vgg13`、`vgg16`、`vgg19`
- `resnet18`、`resnet34`、`resnet50`、`resnet101`、`resnet152`
- `wide_resnet50_2`、`wide_resnet101_2`
- `vit_*` 标准 ViT 系列，覆盖 Tiny/Small/Base/Large/Huge/Giant/Gigantic 常用 patch 和输入尺寸组合
- `dinov2_*` 官方 key、`*_dinov2` timm 别名，以及 `*_reg` / `*_reg4` register-token 变体
- `dinov3_*` 官方 key、`*_dinov3` timm 别名，以及 `_qkvb` 兼容别名

其中：

- 内置分类模型通过 `.wts` 构建 TensorRT network
- `googlenet` 对齐 `torchvision.models.googlenet` 的主分类分支，支持模型注册、构建、推理和特征导出路径
- ViT/DINO 主干复用统一的 Transformer 构建逻辑，支持可配置输入尺寸；DINO 默认输出归一化后的 CLS 特征向量
- DINOv2 适配学习式位置编码、register token 和标准/打包 SwiGLU FFN；DINOv3 适配 RoPE、storage token、LayerScale 和拆分 SwiGLU FFN
- `onnx` 模型通过 ONNX Parser 构建 engine
- 内置分类模型支持按约定的特征 key 导出中间层
- `onnx` 路径当前不支持通过 `featureTensorNames` 选择内部特征层

## 5. 当前已具备的能力

### 5.1 TensorRT engine 生命周期封装

完整的工程化闭环：读取 `.wts` / `.onnx` → 构建 network/engine → 保存 `.engine` → 后续优先复用 → 创建 execution context → 绑定输入输出 → 执行推理或特征前向。

### 5.2 Python 绑定与双路径推理

pybind11 绑定了完整的 Model/ModelConfig API，提供：

- **NumPy 路径**（`infer()`）：标准 CPU 推理，自动管理设备内存
- **DLPack 路径**（`infer_v2()`）：GPU 零拷贝推理，支持 PyTorch CUDA 张量等 DLPack 实现者
- **特征提取**（`forward_features()`）：NumPy 路径的中间层特征导出

### 5.3 分类推理

`samples/model/classification` 提供：

- `.wts` 权重导出（`gen_wts.py`，支持 torchvision 与 timm 后端）
- 标准 ImageNet 预处理，并可通过 `--input-size` 覆盖 ViT/DINO 输入尺寸
- C++ 和 Python 双版本推理样例；分类 logits 按标签打印，DINO 等特征输出按特征向量打印

### 5.4 中间特征导出

- `IModelConfig::setFeatureOnly(true)` 构建纯特征提取模型
- `IModelConfig::setFeatureTensorNames(...)` 声明要导出的中间层
- `forwardFeatures()` 和 `forward_features()` 支持 C++ 和 Python 两路导出
- 各模型支持的特征 key 因网络结构而异（详见 `samples/model/README.md`）

### 5.5 ONNX 推理

`samples/model/onnx` 展示 PyTorch 导出 ONNX → TensorRT 推理的完整链路。

### 5.6 Faiss 图像检索

`src/features` 提供可复用的 `ImageSearch` 类，`samples/model/image_search` 作为命令行样例复用该模块。当前支持图库扫描、特征提取、索引建立/复用、路径映射保存和 top-k 相似检索，并可使用 DINOv2/DINOv3 的 `x_norm_clstoken` 作为紧凑的全局检索向量。

### 5.7 CUDA Resize 算子

具备完整的样例 → 测试 → 基准链路。

### 5.8 版本信息接口

`samples/version` 输出版本、分支、提交号和构建时间。

## 6. 测试体系

### 6.1 C++ 测试（GoogleTest）

| 模块 | 覆盖内容 |
|------|---------|
| `tests/core` | 状态码、异常等基础行为 |
| `tests/util` | CUDA 错误格式化、路径工具 |
| `tests/model` | 模型工厂、生命周期、权重加载、ONNX、分类推理、GoogLeNet、ViT/DINO 配置与构建错误路径、模型 util、DeviceBuffer/HostBuffer、特征配置错误路径保护 |
| `tests/features` | ImageSearch 文件类型判断、默认索引路径、DINO 检索配置、构造参数校验 |
| `tests/cvcuda` | resize 多数据类型/插值方式/异常输入 |

### 6.2 Python 测试（pytest）

测试目录 `tests/python/`，使用 `integration` marker，需要已构建的 `inferrt_model_py` 模块。

| 测试文件 | 用例数 | 验证内容 |
|---------|-------|---------|
| `test_bindings_smoke.py` | 11 | 模型注册表、ModelConfig 默认值、无权重创建、GoogLeNet/ViT/DINO Python 创建 |
| `test_classification_model_zoo.py` | 12 | `gen_wts.py` 共享模型工厂、timm 列表、输入尺寸解析、DINOv3 token pool 参数 |
| `test_classification_parity.py` | 7 | PyTorch vs InferRT `infer()` 分类输出一致性 |
| `test_feature_parity.py` | 5 | PyTorch forward hook vs InferRT `forward_features()` 中间层一致性 |
| `test_infer_v2_parity.py` | 2 | `infer_v2()`（DLPack GPU 路径）vs `infer()`（NumPy 路径）同引擎一致性 |

**容差策略：** 分类和 infer_v2 使用较严格的容差（默认 `rtol=1e-6, atol=5e-2`），特征提取使用较宽松的容差（默认 `rtol=1e-4, atol=1.5e-1`），因跨框架中间层浮点差异更大。通过 `--inferrt-rtol/atol` 和 `--inferrt-feature-rtol/atol` 分别控制。

**测试辅助工具（`tests/python/helpers/`）：**

- `manifest.py` — C++ dump manifest 解析、张量加载、`assert_tensors_close` 断言
- `runtime.py` — 项目路径解析、sample 可执行文件定位、子进程执行、PyTorch/InferRT 分类和特征推理封装

## 7. 构建与依赖

顶层 CMake 主要开关：

- `INFERRT_BUILD_TESTS`、`INFERRT_BUILD_SAMPLES`、`INFERRT_BUILD_DOCS`
- `INFERRT_BUILD_PYTHON` — 是否构建 pybind11 绑定
- `INFERRT_ENABLE_SANITIZER`、`INFERRT_BUILD_BENCHMARK`

关键依赖：

- CUDA、TensorRT、OpenCV
- GoogleTest、Google Benchmark、cxxopts、vtest
- pybind11（Python 绑定需要）
- dlpack（Python 绑定需要，通过 CMake 构建）
- Faiss（可选，`features` 模块和 `image_search` 样例需要；缺失时跳过）

Python 侧依赖：

- `torch`、`torchvision`（生成 .wts、参考推理、测试）
- `opencv-python`（图像预处理）
- `numpy`、`pytest>=8.0`

## 8. 当前项目特征

### 8.1 已形成"库 + 样例 + 测试 + 基准 + 导出"的工程形态

整体结构具备持续演进基础库项目的基本面。

### 8.2 Python 已成为头等公民

通过 pybind11 绑定和 DLPack 协议，Python 侧不仅能用 NumPy 做标准推理，还能用 `infer_v2()` 实现 GPU 零拷贝推理，与 PyTorch 生态无缝衔接。

### 8.3 模型层和 features 模块正在扩展到通用特征服务

特征裁剪网络、`forwardFeatures()`、特征对比和 `ImageSearch` 类，说明项目抽象正在向下游检索/分析类任务延伸。

### 8.4 具备跨框架数值验证能力

pytest 测试套件通过 forward hook 和 DLPack 实现了 PyTorch ↔ TensorRT ↔ NumPy 的多路径交叉验证。

### 8.5 `cvcuda` 仍处于早期，但接口形态已稳定

算子数量还少，但结构已不是一次性 kernel demo，适合继续补齐。

### 8.6 构建系统开始引入可选能力分层

Faiss、pybind11、dlpack 作为可选依赖接入，项目正在从"单一核心库"往"核心库 + 可选 features 扩展"演进。

## 9. 当前边界与不足

- `cvcuda` 目前实装算子主要是 `resize`
- benchmark 仍集中在单算子层面
- ONNX 模型暂不支持基于 `featureTensorNames` 的内部特征导出
- `features` 模块依赖 Faiss；Faiss 缺失时会跳过该模块和对应样例/测试
- `infer_v2()` 仅在 Python 绑定层存在，C++ 侧无对应接口

## 11. 一句话总结

一句话概括：`InferRT` 已从一个 TensorRT 分类推理工程，演进为一个同时覆盖 C++/Python 双语言推理（NumPy + DLPack 零拷贝）、特征提取、可复用图像检索模块和 CUDA 图像算子封装的基础库。
